# AI Governance & Risk Principles — Monday Smart PMO Agent

---

## What the Agent Does

The Monday Smart PMO Agent is a decision-support tool for PMO and project management workflows. It:

- Analyzes Monday-style project data (tasks, sprints, risks, OKRs, team workload)
- Detects risk signals and surfaces them for human review
- Summarizes sprint status, portfolio health, and team capacity
- Maps tasks to OKRs and flags strategic alignment gaps
- Answers natural language questions from project managers
- Generates executive PMO summaries

---

## What the Agent Does NOT Do

- Does not make final project decisions
- Does not approve or reject tasks, sprints, or deliverables
- Does not replace a PM, PMO lead, product owner, or engineering manager
- Does not automatically escalate issues to stakeholders
- Does not modify project data, boards, or task assignments
- Does not send notifications, messages, or reports on its own

---

## Human-in-the-Loop Principle

**The agent supports human decision-making. It does not substitute for it.**

The agent detects risk signals, summarizes available data, highlights gaps, and suggests actions. A qualified human must:

- Review agent outputs before acting on them
- Approve any escalations, reprioritization decisions, or delivery changes
- Validate risk assessments against context the agent may not have
- Make final calls on sprint planning, resource allocation, and strategic trade-offs

The value of the agent is in reducing manual analysis effort — not in removing human judgment.

---

## When Human Approval Is Required

Human approval is always required before:

- Escalating a risk to a stakeholder or leadership
- Reprioritizing sprint scope or backlog items
- Reassigning work between team members
- Changing OKR targets or delivery timelines
- Communicating project status externally
- Making any operational or delivery decision based on agent output

---

## Data Limitations

### Demo Mode

In demo mode, the agent uses local fictional data representing a company called TechCo and a product called FlowHQ. This data is:

- Realistic but not real
- Static (does not update in real time)
- Designed to exercise all PMO flows (health, sprint, risk, OKR, capacity)

Demo mode outputs should not be treated as actual project status.

### Real Integration Mode (Future)

When connected to a live Monday workspace via `PMO_DATA_SOURCE=monday_api`, the agent will reflect real project data. Limitations to be aware of in that mode:

- The agent reflects only the data available in the connected Monday board(s)
- Data quality depends on how consistently teams update their tasks and statuses
- The agent cannot reason about context that is not captured in the data (verbal agreements, informal decisions, email threads)
- Outdated or incomplete project data will produce unreliable analysis

**Risk:** If a PM acts on agent analysis without validating data freshness, they may make decisions based on stale project state.

---

## Risk of Incomplete or Outdated Project Data

Project data is often incomplete or delayed in real environments. Common failure modes:

| Data Issue | Agent Risk |
|-----------|-----------|
| Tasks not updated after completion | Agent reports stale blockers or false risks |
| OKR links not maintained | Agent underreports OKR alignment |
| Sprint assignments not reflecting actuals | Capacity analysis may be inaccurate |
| Risk registry not maintained | Agent misses real risks or shows resolved risks |

**Mitigation:** Establish team norms for keeping Monday boards updated. Treat agent output as a starting point for PM review, not a final status report.

---

## Demo Mode vs. Real Integration Mode

| Aspect | Demo Mode | Real Integration Mode |
|--------|----------|-----------------------|
| Data source | Local JSON files | Live Monday API |
| Data freshness | Static (as of demo) | Real-time (as of last sync) |
| API credentials required | No | Yes (`MONDAY_API_TOKEN`) |
| Suitable for | Portfolio demos, development, testing | Production PMO workflows |
| Current status | Active (default) | Future — architecture ready |

Switch modes via environment variable: `PMO_DATA_SOURCE=monday_api`

## Responsible Use Principles

1. **Transparency:** Always disclose to stakeholders that a summary or analysis was generated by an AI assistant.
2. **Validation:** Verify agent outputs against source data before presenting them as factual status.
3. **Human accountability:** A human PM or PMO lead remains accountable for all project decisions, regardless of agent input.
4. **Data minimization:** Do not connect the agent to boards containing sensitive personal, financial, or confidential information beyond what is needed for PMO analysis.
5. **No automation of consequential actions:** Do not build automated pipelines that act on agent output without human review.

---

## Right-Size Engineering Principle

This project follows a Right-Size Engineering approach:

- Build what is needed for the current use case — no more, no less
- Prefer simple, understandable modules over sophisticated frameworks
- Avoid architecture that requires explanation before it can be maintained
- Add complexity only when a clear, concrete need justifies it
- Keep the demo runnable without cloud infrastructure, external accounts, or production credentials
- Future extensions (live Monday API, multi-agent, MCP server) are possible but not added until they are needed

The goal is a project that is easy to understand, easy to extend, and easy to demo — not one that demonstrates architectural sophistication for its own sake.
